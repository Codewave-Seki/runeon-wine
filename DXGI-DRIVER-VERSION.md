# Optional DXGI driver version correction

[English](DXGI-DRIVER-VERSION.md) | [Chinese](DXGI-DRIVER-VERSION.zh-CN.md) | [Japanese](DXGI-DRIVER-VERSION.ja.md)

Candidate `.11` includes independent LGPL-2.1-or-later `runeondxgi.dll` in `0105-dxgi-driver-version.patch`. It uses public COM/SetupAPI and Wine's GPU LUID property; it does not incorporate the unlicensed external shim.

Only successful `CheckInterfaceSupport` results equal to -1 are corrected, using one exact LUID match and a valid existing four-part `DriverVersion`. Other versions, HRESULTs, null outputs, ambiguous or unknown devices retain provider behavior. A bounded process-lifetime LUID cache avoids repeated device enumeration. Original COM objects are returned; provider tables are registered under a lock, the module is pinned, and page protection retains any execute permission while installing the hook.

**The product defaults this experimental correction off.** A local persistent preference may explicitly enable it; disabling restores the prefix's original DXGI and does not enable it again on subsequent preparation. Wine's synthesized registry version is not a vendor's real driver/package version. An Apple device reported as AMD by DXGI still has an Apple-derived fallback version; game-specific vendor parsing has not been validated.

The App leaves the shared runtime `dxgi.dll` unchanged and installs the wrapper/provider pair only in the selected prefix. The wrapper retains its `runeondxgi.dll` export-library identity so Wine resolves the optional builtin. Ownership, destinations and required source files are checked before preparation, and the dependency is published before the wrapper in the existing prefix transaction. Initialization or repair by wineboot may replace the wrapper, so the App reapplies policy before per-game launch preparation. The unpublished runtime-wide prototype is restored from its preserved original.

The user-local Apple provider is renamed to `rxdg.dll` and uses the local matching unix alias. It is loaded at module attachment to preserve original provider initialization before a caller creates a D3D device. Provider load failure tries the bare module name and emits an explicit debug message; bare-name fallback did not resolve a missing prefix provider in the tested runtime and is not the safety boundary. Seed packaging excludes private providers and backups. This repository contains no Apple private binaries or per-game matching.

Build through the normal Wine build with the explicit `.11` definition. Policy check: `x86_64-w64-mingw32-gcc -std=c11 -I /path/to/patched/wine/dlls/runeondxgi tests/dxgi-driver-version.c -o /tmp/dxgi-policy.exe -lsetupapi -ladvapi32 -ldxguid -luuid`; also build with i686 and run through the product's authorized isolated Wine probe. It covers unique-match replacement, cache reuse, duplicate/missing devices, unchanged returns and executable page protection.

Local evidence is recorded in Runeon T798: x64/i386 module builds, policy checks, App compilation, prefix scope, persistent disable, rollback and original/fixed/restored API checks pass. Factory calls and EnumAdapterByLuid are corrected. D3D11 device-first creation succeeds and preserves its original -1 result; it is not a covered correction entry point. EnumWarpAdapter preserves the original unsupported result. A delayed-provider-initialization regression was reproduced and fixed. No seed is published, and no game compatibility is claimed.
